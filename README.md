# 试题提取 skill · 高中化学试卷 docx → Markdown

> 把「高中化学试卷 `.docx`」**逐件无损**转换成结构化 Markdown（成品 md + `images/` + `work/` + `转换说明.md`），
> 核心难点在于 **MathType/OLE 二进制公式还原、OMML 原生公式线性化、装置图语义判读**——
> 这些纯靠机器抽不出来，所以本项目走的是 **「脚本做确定性部分 + 判据卡住边界 + 人眼裁决语义」** 的路子。

```
.docx ──▶ 解包 ──▶ 内容流 ──▶ 公式还原 ──▶ 骨架 ──▶ 成品 md ──▶ 机审 10 项 ──▶ 人工核 ──▶ 交付
                     │            │            │           │            │
                 probe 三连判   MTEF5/OMML   占位符零残留  audit.py   _sk_balance 复算
```

| 指标 | 数值 |
|---|---|
| 脚本 | 47 个流水线脚本（约 5.4k 行）+ 5 个工程校验工具，33 个 Core 指纹基线 |
| 流水线阶段 | S0 普查 → S1–S8（子代理）→ S9 验收（主代理）→ S10 收口 |
| 机审判据 | `audit.py` 10 项（须 `FAILS: 无`）＋ `_sk_balance.py` 守恒复算（须退出码 0） |
| 经验沉淀 | U1–U196 条通用改进清单（多批次实证） |
| 已验证 | 10 件完整批次、1491 个 MathType OLE 对象零剩余率 100% |
| 许可 | MIT |

## 这个项目解决什么问题

用 Word 出的化学试卷，公式全是 **MathType OLE 对象**或 **OMML 原生公式**，
排版靠浮动文本框 + 绝对定位的图。想转成 Markdown 给 AI 读、给网站用、给检索用，难在：

1. **公式是二进制**——`mtef_render.py` 逐字节解析 MTEF5 格式，还原成线性化学文本；
2. **上下标会碎**——`vertAlign` 上标槽、Unicode 上下标、Symbol 字体私有区码位（PUA）三种机制混用；
3. **"零残留"不等于"没出错"**——脚本能保证抽取无损，但**源文本身**的笔误（漏电荷、写错化学式）
   机器一个都测不出来，只能人眼通读（本项目 [U178](#五踩过的坑选摘) 的核心教训）。

所以本项目不只是一个转换脚本，而是一套 **有判据、可验收、可断点续做** 的作业规程。

## 快速开始

### 1. 环境

```powershell
# Python 3.9+（开发环境为 3.13/3.14）
pip install pillow olefile pymupdf
```

| 依赖 | 用途 | 必需性 |
|---|---|---|
| **olefile** | 读 MathType OLE 复合文档（`mtef_render.py` / `probe_ole.py`） | 必需（S3） |
| **Pillow** | 图片白底合成、放大、空白像素判定 | 必需（S4/S7） |
| **PyMuPDF** | PDF 文本层提取 + 高倍裁切目验 | 必需（S9） |
| **LibreOffice** | WMF/EMF → PNG、docx → PDF 交叉验证 | 必需（S3/S9） |
| LLM Agent | 执行 S1–S8 / S9 判断 | 必需 |

> 其余全部为标准库（`zipfile` / `xml` / `struct` / `re` / `hashlib` …），无其他三方包。
> 全流程**完全离线**，不上传任何试卷内容。

## 题库（`_题库/`）

流水线跑通后，成品 md 会散落在各批次目录、文件名带着「学年/出版社/品牌角标」等噪声。
`_题库_sync.py` 负责把它们**重新组织**成本仓库内的分类题库：

```powershell
# 预览分类与命名（不落盘）
python _题库_sync.py --src "<课后题工作目录>" --dry-run
# 实际迁移（--reset 先清空重建，保证幂等）
python _题库_sync.py --src "<课后题工作目录>" --reset
# 校验：每张配图都能在同目录 images\ 里找到
python _题库_sync.py --src "<课后题工作目录>" --verify
```

**四条原则**

1. **正文逐字节不动** —— 题库 md 是已过机审（`FAILS: 无`）的交付件，复制时不加头、不改一字；
   重命名只作用于**文件名**，原始名与源路径写入 `题库清单.json` 供溯源。
2. **命名规范化** —— `<类目码>-<两位序号>_<精简主题>.md`，如 `NI-08_第五章第二节氮及其化合物·氨气.md`。
   同桶重名时自动从原始名提取线索消歧（`·氨气`／`·硝酸的制备`）。
3. **四层分类** —— `01_元素专题`（钠/氯/铁铝/氮/硫 + 综合）／`02_题型专题`（工业流程/实验探究/按题型归类）
   ／`03_章节同步练`／`04_阶段检测卷`。
4. **配图随迁** —— 题库 md 里 `![](images/x.png)` 是**相对路径**，故每份题库自带 `images\`，
   `--verify` 逐张确认可达，避免断图。

> ⚠ **`_题库/` 已 gitignore**：试题/答案/解析的著作权属教辅出版社与作者，
> 公开仓库分发有合规风险，故只在本地维护。`_题库_sync.py` 与分类规则本身入库，可随时从源目录重建。

## 五、踩过的坑（选摘）

完整的 **U1–U196** 见 [`_skill经验归档.md`](_skill经验归档.md)，每条都带「背景 + 实证数据」。
以下是最值得警惕的几类：

<details>
<summary><b>U178 · 「零残留」只证明抽取无损，不证明源文正确</b></summary>

机审 10 项全过、`FAILS: 无`，但源文里仍有三处语义级笔误：
`NaNO₃得到3个电子`（应为 NaNO₂）、`c(HCO₃²⁻)`（应为 HCO₃⁻）、`OH` 漏电荷。
**没有任何一项由自动判据告警**——只有人眼通读 `content_stream.txt` 和
`_s_formulas.txt`（全量公式逐行）才能发现。

⇒ **S3 后固定做「两读」**，且**语义/计量级缺陷只能人眼发现**。
</details>

<details>
<summary><b>U93 · 命令行不直传中文路径</b></summary>

PowerShell/Git Bash 下把中文路径作 argv 直传会被 GBK 转码损坏，
脚本收到乱码报 `FileNotFoundError`，**极易误判为脚本缺陷**。

⇒ 中文路径只能待在 UTF-8 文件里（`_target.txt`），由 Python 自己读。
注意 `subprocess.run([PY, script, 中文路径])` **列表参数不经 shell，不受影响**。
</details>

<details>
<summary><b>U161 · Symbol 字体的 PUA 码位是机审盲区</b></summary>

Word 把 Symbol 字形按 `U+F000+码位` 直接存进 `w:t`（**不是** `w:sym`，
所以 S0 普查测不到），原样漏进成品 md 残留不可渲染字符，
而 **audit 10 项全过**。本件 5 处：`U+F028→(`、`U+F029→)`、`U+F02D→-`、
`U+F0BE+U+F0AE→→`（两码位合成一个长箭头）。

⇒ S9 固定加「成品 md 全码位扫描」（枚举 U+E000–U+F8FF 打印上下文）。
**通用教训：凡「静默降级」分支（判不出就原样返回）都必须有落盘计数，否则该缺陷对全部自动判据不可见。**
</details>

<details>
<summary><b>U104 / U167 · 「方程式不守恒」先分三类</b></summary>

① **漏写** → 修正（正确形态须由同句**唯一确定**）；② **考点干扰项**（故意的错方程式）→ 保留；
③ **非方程式片段** → 假阳性。搞错分类就会把干扰项「修好」，反而破坏了试题的考点。
</details>

<details>
<summary><b>U180 · 清理动作自己也会触发判据</b></summary>

在 `figure_desc.md` 表头写说明文字「亦不含全角 `＝/＋`」，
结果**说明文字本身**里的全角字符被整文件扫描判为违规。
⇒ 图述文件**全文**（含说明段）禁用全角符号，举例一律改用文字描述。
</details>

## 裁决授权

为保证「一个会话一件」的交付节奏，**待裁决项由主代理自行裁决，不逐项问用户**，
只需在《转换说明》与每轮汇报的【本轮裁决】清单中说明「处理了什么、依据是什么」：

| 类别 | 处置 |
|---|---|
| 配平/计量类源文错误 | **修正**（正确形态须由同句唯一确定） |
| 字形/符号形态类（全角 ＞＜、U+3000、作答横线） | **原样保留**并逐条列出 |
| 全篇系统性偏离 | **整篇保留** + 登记，不得局部修补 |
| 图描述不唯一/低置信 | 维持**集合式描述**（只列容器与标注，不臆造） |
| 源文异常件（近乎空） | 判「源文件异常」→ 跳过该件并登记，继续下一件 |

**唯一的例外**：存在需用户拍板的〔存疑〕时，主代理会停下询问。
