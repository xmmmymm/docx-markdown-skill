## 〇之四、反循环机制（本批**强制** · 根治"对某一内容重复思考且不干活"）

> **为什么现有经验挡不住**：氯序7、硫序2/序4/序6 均已把 U43/U69/U74 写进派发指令，循环**照样发生**。
> 根因不是"提醒不够"，而是两条结构性缺陷：
> ① 流程让子代理**必须反复 Read 大图（可达数百 KB）才能判图** → 上下文被图吃掉；
> ② "是否在推进"**只能靠子代理自己汇报** → 它循环时既不报错也不停，主代理无从察觉。
> ⇒ 本批改为**机制化三件套**：**判图卡片（先机器后人工）＋ 进度契约（每图 append，磁盘可观测）＋ 看门狗（主代理外部按磁盘事实判停摆）**。

### 1. 判图卡片（派发前由主代理跑，产物先于子代理存在）

```
& $py "_工具库\_n_imgprep.py" "<输出目录>" --grid 84x30
```

- 产物：`work\_imgcards\<name>.txt`（尺寸／暗像素／**空白判定**／**84×30 粗网格 ASCII 像素图**／16×16 灰度签名）、`_index.md`（汇总 + 同图组）、`_dup.json`。
- **派发指令必须写死**：判图时 **Read 卡片（2–3 KB 纯文本），不得 Read 原图**；**仅当卡片不足以判定、且图 <1000 px 时**才允许 Read 原图 **1 次**。
- 同图组（16×16 签名 L1 < 64）→ **直接复用描述、零目验**（U68）；卡片已给出暗像素 ⇒ 空白图删改**无需再看图**（U8 铁证自动落盘）。
- 效果：单图进入上下文的量从 **≈240 KB 图片**降为 **≈2.5 KB 文本**，同一张图"读不懂就再读"的诱惑与成本同时消失。

### 2. 进度契约（写进派发指令，让"推进"可被外部观测）

| 契约 | 内容 |
|---|---|
| 逐张落盘 | `figure_desc.md` **每判 1 张即 append 1 行**（S4）；**禁**整读后重写、**禁**先写中间文件再拼装 |
| 心跳 | 每 5 张发一条极简心跳（已判 N/M）；S0/S2/S6/S8 各一条 |
| 禁自造放大图 | 需要放大时**用卡片里的 ASCII 网格**；确需裁图须 ≤1 次且**不得**命名 `zoom_*`/`_tmp*` |
| 主代理侧 | **只看磁盘增长，不看口头回报**（U76） |

### 3. 看门狗（主代理外部轮询，**自动**判停摆）

```
# 阻塞式（短轮询）
& $py "_工具库\_n_watchdog.py" "<输出目录>" --interval 60 --times 20 --stall 2
# 后台式（推荐，不占命令行；结果随时读 work\_watchdog_out.txt）
Start-Process -FilePath $py -ArgumentList '_n_watchdog.py "<输出目录>" --interval 60 --times 20 --stall 2' -WindowStyle Hidden
```

**判据（任一命中即 `STALLED`，退出码 3）**
1. **零增长**：连续 `--stall` 次轮询，`<输出目录>` 无任何新增/变更文件且 `figure_desc.md` 行数不变；
2. **污染信号**：出现 `zoom_*` / `_tmp*` / `_app*` / `*_profile.txt` / `*_crop.png`（已排除工具库 `.py`，不会误报 `zoom_profile.py`）；
3. **单图自旋**：同一 image 的派生文件数 > 3。

**处置（不抢救、不提醒）**：`shutdown_request` 停用该成员 → 删污染源 → 派**干净上下文**新棒，指令中**直接给出**：已判清单 + 剩余区间 + `_imgcards` 路径 + 同图组（避免重新探索）；**连续两棒失败 → 主代理兜底**（U74，用客观手段替代目验）。
